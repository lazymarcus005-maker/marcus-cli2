# T-003 — Trusted Configuration, Model Binding and Repository Instructions

**Phase:** 1 — Agent Foundation & Safety
**Depends on:** T-001, T-002
**Sources:** spec.md sections 23–25, 30–31, 42–43; handoff.md sections 5.4, 10

## Goal
Implement the canonical v1.1 configuration and instruction trust model so repository content cannot elevate credentials, endpoints or execution policy.

## Scope
Implement a typed schema for models/providers/aliases, context, model_profiles, run, execution, retrieval, logs and features. Resolve defaults → global config → allowed project fields → explicit CLI overrides. MACUS_CONFIG selects the user config path and --config wins.

Project config may select an existing trusted model alias and bounded retrieval/features only. Bind credential references to normalized trusted provider identity/base URL. Reject inherited-key plus project-supplied endpoint combinations. Keep TLS validation enabled by default; local HTTP requires explicit user configuration.

Resolve MACUS.md, AGENTS.md and CLAUDE.md from repository root to target directory. More specific directory guidance wins within its subtree; at the same directory MACUS > AGENTS > CLAUDE. Preserve non-conflicting instructions and path/hash/scope provenance.

## Acceptance Criteria
- [ ] Forbidden project endpoint/key/policy override fails visibly.
- [ ] Secrets never appear in settings, errors, manifests or project files.
- [ ] Settings report resolved value provenance.
- [ ] Sibling-directory instructions do not override one another.
- [ ] Repository guidance cannot authorize credentials/endpoints/plugins/policy elevation.
- [ ] Legacy budget aliases fail with migration hints.
- [ ] semantic_search and telemetry enablement are rejected in V1.
- [ ] Enabling a not-yet-implemented feature returns an explicit error.

## Tests
Cover config precedence, aliases, missing env vars, redaction, forbidden overrides, instruction hash changes, nested scopes and duplicate Pi resource-loader prevention.
