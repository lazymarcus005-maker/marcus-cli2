# T-015 — Durable Task Engine and Bounded Coding Workflow

**Phase:** 4 — Coding Workflow & Evidence
**Depends on:** T-004, T-014
**Sources:** spec.md sections 5.2–5.3, 35, 45; handoff.md sections 6–7

## Goal
Turn user intent into durable tasks and run the coding workflow without unbounded autonomous loops.

## Scope
Implement session-scoped tasks with statuses pending, in_progress, completed, blocked and skipped. Store sessionId, ID, title, status, related files/symbols, notes, timestamps and optional evidence IDs. Enforce valid transitions and at most one in-progress task per active run by default.

Implement Agent Harness stages: inspect/understand → discover → plan → tasks → implement → targeted tests → inspect/fix → broader tests → diff/review → finish. Pi remains owner of the inner model/tool loop.

Enforce run limits: default 40 model turns, three consecutive no-progress attempts with the same normalized failure fingerprint and no relevant source change, and 30 minutes per run. User may configure limits or explicitly extend a paused run.

Add /tasks command.

## Acceptance Criteria
- [ ] Tasks survive process/session resume.
- [ ] Completing a task never implies tests passed.
- [ ] Only one mutating run exists per worktree.
- [ ] User cancellation halts continuation.
- [ ] Repeated failure without progress pauses with a blocker.
- [ ] Automatic retries and continuations count toward run limits.
- [ ] Agent does not restart planning after implementation unless task/assumptions materially change.
- [ ] /tasks shows progress, blockers and current evidence references.

## Tests
Task transitions, persistence/resume, no-progress fingerprinting, run/turn/time caps, cancellation and explicit continuation after a pause.
