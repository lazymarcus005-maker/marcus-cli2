# T-009 — Bounded Source Search

**Phase:** 2 — Code Retrieval & Freshness
**Depends on:** T-005, T-008
**Sources:** spec.md sections 7, 13–14; handoff.md section 8

## Goal
Provide deterministic repository search with bounded output, explicit partial-result semantics and no shell injection.

## Scope
Implement search_code using ripgrep with structured argv. Inputs: query, optional path, fileType, maxResults, caseSensitive, literal and cursor. Literal search is the default; regex is opt-in.

Enforce repository inclusion policy, ignore rules, authorized paths, global result bound, configured timeout and token/output limits. Bind cursors to the query and source/index generation.

Return path/range matches plus returnedCount, nullable totalKnown, truncated, nextCursor when available and a reason for partial results.

## Acceptance Criteria
- [ ] No user query is interpolated into a shell command.
- [ ] Default global maximum is 100 matches and default timeout is 10 seconds unless configured lower.
- [ ] No-match, invalid-regex, timeout, cancellation and process failure are distinct outcomes.
- [ ] Exact totals are not claimed unless actually counted.
- [ ] Stale cursors are rejected or search restarts explicitly.
- [ ] .gitignore, .macusignore, policy-denied paths and binary/generated/dependency exclusions are respected.
- [ ] Symlink escape outside the authorized worktree is rejected.
- [ ] Search remains usable while structural index is cold or degraded.

## Tests
Fixtures for literal and regex search, global truncation, cursor invalidation, ignored paths, symlink escape, timeout, cancellation and invalid regex.
