# T-021 — Reference, Dependency, Impact Tools and Phase 6 Gate

**Phase:** 6 — Lightweight Relationships
**Depends on:** T-020
**Sources:** spec.md sections 12–13, 36, 45; handoff.md sections 6, 8, 13

## Goal
Expose relationship and impact tools that are useful for inspection and test prioritization without treating partial graph coverage as proof.

## Scope
Implement find_references, find_dependencies, find_dependents and impact.

Return bounded metadata before source content:
- target symbol and source version;
- confirmed references;
- candidate references;
- unresolved relationships;
- possible tests;
- evidence per relationship;
- explicit coverage status and limits.

If completeness is unknown, return coverage: partial. Zero graph results must never imply zero callers. Candidate relationships may promote files to RELATED context but must retain uncertainty.

Use impact only to prioritize inspection and targeted tests. When confidence/coverage is insufficient, broaden text search and relevant test scope.

Create docs/phase-6-evidence.md.

## Acceptance Criteria
- [ ] Confirmed/candidate/unresolved results remain distinct in CLI/tool output.
- [ ] Zero results with partial coverage never claim no callers/dependents.
- [ ] Same-name matches do not become confirmed callers without resolver evidence.
- [ ] Incomplete graph cannot be used to skip broader relevant tests.
- [ ] Graph disabled retains ordinary search, smart reads and coding workflow.
- [ ] Relationship output is bounded and source is fetched on demand.
- [ ] Alias/overload/dynamic fixtures demonstrate honest uncertainty.
- [ ] Common phase gate tests/typecheck/build/lint, CLI verification and diff review are recorded.

## Evidence
Include graph resolver/version, fixture coverage, relationship evidence, broader-test fallback and disabled-feature behavior.
