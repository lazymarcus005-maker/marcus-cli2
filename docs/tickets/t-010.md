# T-010 — Tree-sitter Symbol Index and Incremental Cache

**Phase:** 2 — Code Retrieval & Freshness
**Depends on:** T-009
**Sources:** spec.md sections 8, 14; handoff.md section 8

## Goal
Build lightweight structural intelligence for TS/TSX, JS/JSX and C# with explicit coverage limits and freshness guarantees.

## Scope
Pin Tree-sitter bindings, grammars and queries. Extract declarations, signatures, ranges and import/export or using/base-type syntax required by the spec. Generate disambiguated symbol IDs using language, normalized path, qualified name, kind and signature/location information.

Store rebuildable structural cache in .macus/cache/index.db with canonical path, size, high-resolution mtime, content hash, language, parser/query/resolver versions, parse status and index generation.

Update one changed file transactionally so readers never observe half-updated symbols/edges. Lazy-load parsers and keep indexing bounded/in-process.

## Acceptance Criteria
- [ ] TS/TSX, JS/JSX and C# fixtures produce expected declarations/signatures/ranges.
- [ ] Unsupported languages explicitly report no structural coverage and retain text search/range read.
- [ ] Parse errors produce partial coverage metadata, not invented symbols.
- [ ] Duplicate names return disambiguated candidates instead of silently choosing one.
- [ ] Same-size external edits are detected by hash before serving cached source.
- [ ] Delete, rename, checkout and parser/schema upgrade invalidate affected records.
- [ ] Files over the default 1 MiB parse limit fall back to bounded text retrieval.
- [ ] Corrupt cache can rebuild without touching state.db.

## Tests
Language fixtures, duplicate names, syntax errors, external edit, rename/delete/checkout, parser-version invalidation, oversized file and corrupt cache recovery.
