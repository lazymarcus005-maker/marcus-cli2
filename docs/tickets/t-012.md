# T-012 — Working Set, Context Tiers and Deterministic Selector

**Phase:** 3 — Context Runtime
**Depends on:** T-006, T-011
**Sources:** spec.md sections 6.1–6.3, 6.6, 13; handoff.md sections 5.1, 8

## Goal
Select the smallest useful fresh source context deterministically while keeping working-set state separate from actual request inclusion.

## Scope
Maintain session-scoped ACTIVE, RELATED, DISCOVERED and STALE working-set entries with canonical path, source hash, symbols, last access and selection reason. Keep working-set status independent from HOT/WARM/COLD tier.

Build deterministic selector candidates carrying source identity/version, token estimate, tier, reason and evidence. Deduplicate equal fragments and merge overlapping ranges before scoring.

Initial scoring supports non-negative weights for exact path/symbol match, active working-set membership, edited-file relevance, related test, task keyword match and recent access. Graph contribution is disabled until Phase 6.

Reserve mandatory instructions and protocol obligations before optional ranking. Use stable path/symbol ordering for ties.

## Acceptance Criteria
- [ ] Working-set membership never implies automatic request inclusion.
- [ ] HOT/WARM/COLD never bypass freshness or budget checks.
- [ ] Equal/overlapping fragments are deduplicated.
- [ ] Low-confidence retrieval triggers broader text search/additional source reads.
- [ ] Stale entries cannot be presented as current.
- [ ] Item/age eviction only removes retrieval metadata, never files or durable decisions.
- [ ] Dynamic priority changes across pre-edit, post-edit and test-failure stages are deterministic.

## Tests
Working-set transitions, deduplication, stable tie ordering, stale entries, budget pressure and stage-aware priority cases.
