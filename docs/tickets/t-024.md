# T-024 — Packaging, Installation, Documentation and V1 Release Gate

**Phase:** 7 — Release Hardening
**Depends on:** T-022, T-023
**Sources:** spec.md sections 40–46; handoff.md sections 6–7, 15–16

## Goal
Verify Macus Code can be installed and used as a truthful V1 release with all prior gates still green.

## Scope
Validate clean installation on macOS arm64 and the chosen Linux environment using the pinned Node runtime/package manager. Audit package contents, executable wiring, lockfile, Tree-sitter/SQLite native dependencies, third-party notices/licenses, README/setup instructions, config examples, feature flags, data paths and uninstall/cleanup guidance.

Run the complete fixed correctness/recovery suite and every earlier phase gate. Exercise an end-to-end coding task through instruction resolution, bounded retrieval, task tracking, current-source edit, appropriate tests/fix loop, review, durable state and resume. Include an interrupted-run demonstration showing unknown side effects are not replayed automatically.

Create docs/phase-7-evidence.md and final implementation report.

## Acceptance Criteria
- [ ] All Phase 1–6 required gates remain green or an explicit release blocker is recorded.
- [ ] Clean macOS arm64 install works.
- [ ] Chosen Linux install works or is explicitly blocked with reproducible evidence.
- [ ] macus executable launches from a clean install.
- [ ] Live endpoint compatibility evidence exists for the claimed provider/profile.
- [ ] Recovery interruption matrix passes or unsupported states pause safely.
- [ ] Benchmark report and raw data are published.
- [ ] License/attribution obligations are documented.
- [ ] Feature limitations and non-goals are documented honestly.
- [ ] No preview is labelled production-ready before this gate.
- [ ] No commit/push/merge/publish occurs without applicable authorization.

## Final Report
State what changed, exact validation performed, evidence locations, remaining blockers, limitations and the tested source revision/worktree snapshot.
