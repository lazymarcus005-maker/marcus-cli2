# T-017 — Git Context, Diff Attribution, Review and Phase 4 Gate

**Phase:** 4 — Coding Workflow & Evidence
**Depends on:** T-015, T-016
**Sources:** spec.md sections 15–16, 33, 37, 45; handoff.md sections 6–7, 12

## Goal
Make Git a bounded context source and complete work only from fresh diff/test/task evidence.

## Scope
Implement git_state plus bounded git_diff, git_log, git_show and git_blame where enabled. Do not inject a full diff every turn.

Track initial Git state and file hashes to distinguish agent, pre_existing and external_or_unknown changes. Add /diff with bounded output and attribution. Before completion inspect current diff, task state, current test/build evidence, unexpected changes and remaining type/syntax failures.

Review output must contain:
- Changed
- Tested, including commands, snapshot and evidence IDs
- Remaining Risk
- Unresolved Issue

Create docs/phase-4-evidence.md.

## Acceptance Criteria
- [ ] User staged/unstaged/untracked changes survive normal agent work.
- [ ] Diff attribution is based on observed hashes/writes, not dirty status alone.
- [ ] Review never reuses test evidence from before the final relevant edit.
- [ ] Pre-existing failures are distinguished from introduced failures with evidence.
- [ ] Review does not commit, push, merge or publish automatically.
- [ ] Git context is bounded and can be disabled without breaking mandatory repository identity checks.
- [ ] Task state survives resume and matches review evidence.
- [ ] Run limits/blockers are demonstrated through CLI.
- [ ] Common phase gate tests/typecheck/build/lint and diff review are recorded.

## Tests
Dirty worktree fixtures, external edits during run, bounded diff, stale test evidence, pre-existing failure and disabled git-context behavior.
