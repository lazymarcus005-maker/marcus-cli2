# T-008 — Phase 1 Benchmark Baseline and Evidence Gate

**Phase:** 1 — Agent Foundation & Safety
**Depends on:** T-002 through T-007
**Sources:** spec.md sections 39, 45–46; handoff.md sections 6–7, 14–15

## Goal
Close Phase 1 with reproducible evidence rather than implementation claims.

## Scope
Create the benchmark harness and an unmodified pinned Pi baseline. Define versioned fixtures and raw result storage.

Record Node/Pi/package versions, OS/hardware, repository/fixture revision, endpoint/model/version and generation settings, context/output limits, starting workspace revision, task oracle, cache condition, all input/output tokens including retries/compaction where reported, latency, first-useful-edit time, tool calls, peak context and CLI RSS.

Create docs/phase-1-evidence.md proving Pi capabilities, request bounds/protocol, cancellation, crash-after-write reconciliation, endpoint trust, preservation of unrelated edits, CLI exercise and baseline commands/results.

## Acceptance Criteria
- [ ] Deterministic mock-provider compatibility run exists.
- [ ] Actual configured endpoint is tested when available; otherwise the live gate is explicitly blocked.
- [ ] Baseline and Macus conditions are recorded separately.
- [ ] No performance improvement claim is made without measured paired data.
- [ ] Evidence references exact commands/logs/snapshots.
- [ ] Failed or absent required checks are not marked passed.
- [ ] Tests, typecheck, build and configured lint pass or blockers are documented.

## Out of Scope
Final Phase 7 benchmark claims and production-ready labeling.
