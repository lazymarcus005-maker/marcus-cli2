# T-014 — Change-Aware Context and Phase 3 Gate

**Phase:** 3 — Context Runtime
**Depends on:** T-012, T-013
**Sources:** spec.md sections 6, 6.6, 16, 22, 45; handoff.md sections 6–7

## Goal
Ensure edits and external source changes immediately invalidate superseded context and that the final request remains valid under model/profile changes.

## Scope
After a successful edit or observed source change:
- invalidate old source fragments and affected evidence;
- refresh changed file index records;
- mark superseded versions;
- collect bounded callers/interfaces/tests metadata;
- preserve candidate relationship uncertainty;
- attribute changes as agent, pre-existing or external/unknown from recorded hashes/writes.

Only verified current source may enter the effective request. Historical source is retained only for explicit before/after comparison and must be labelled by version.

Implement request rebuild on smaller-model switch and verify all category and protocol constraints. Keep stable system/tool/instruction text byte-stable where practical without reordering protocol messages.

Create docs/phase-3-evidence.md.

## Acceptance Criteria
- [ ] Repeated reads never duplicate source in the effective request.
- [ ] Current source replaces superseded source after edits.
- [ ] External editor changes invalidate stale fragments.
- [ ] Git checkout/HEAD changes reconcile working-set freshness.
- [ ] Smaller-model switch stays within its validated budget or visibly pauses.
- [ ] All tool call/result groups remain valid after omission/compaction.
- [ ] Actual provider payloads match request manifests.
- [ ] Common phase gate tests/typecheck/build/lint and CLI verification are recorded.

## Evidence
Capture before/after manifests for edits, external changes, repeated reads and smaller-context model switching.
