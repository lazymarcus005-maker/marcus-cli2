# T-020 — Optional Lightweight Relationship Graph

**Phase:** 6 — Lightweight Relationships
**Depends on:** T-010, T-019
**Sources:** spec.md sections 11, 14, 31, 45; handoff.md sections 5.3, 8, 10

## Goal
Add an optional SQLite relationship graph that improves retrieval without overstating semantic certainty.

## Scope
Store graph data in .macus/cache/index.db for:
- file imports file
- file contains symbol
- symbol references symbol
- symbol implements interface
- test references symbol

Every edge stores edge type, source ID, nullable target ID, target text, resolution, confidence, evidence path/range/hash/extraction method, resolver version and index generation.

Resolution is confirmed, candidate or unresolved. Confirm only containment and explicitly supported uniquely resolved cross-file cases. Same-name text matches are candidates, never proof of a direct caller. Unsupported aliases, overloads, dynamic dispatch and interface/DI uncertainty remain explicit.

Invalidate edges transactionally on source changes, delete/rename and grammar/query/resolver/schema changes.

## Acceptance Criteria
- [ ] Duplicate names never create false confirmed edges.
- [ ] Unsupported dynamic/alias/overload cases remain candidate or unresolved.
- [ ] Every non-containment relationship has evidence and coverage metadata.
- [ ] Deleted/superseded symbols do not leave dangling authoritative edges.
- [ ] Graph absence/corruption does not block search/read/edit.
- [ ] code_graph false removes graph scoring and certainty claims.
- [ ] Enabling graph before the Phase 6 implementation is available fails clearly.
- [ ] No graph server, compiler semantic engine, embeddings or mandatory language server is introduced.

## Tests
Duplicate-name, alias, overload, dynamic-call, delete/rename, partial resolver coverage, disabled graph and corrupt-cache fixtures.
