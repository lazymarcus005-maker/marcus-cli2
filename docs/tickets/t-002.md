# T-002 — PiAgentKernel Compatibility Adapter

**Phase:** 1 — Agent Foundation & Safety
**Depends on:** T-001
**Sources:** spec.md sections 4, 5.1, 6, 21, 42, 45; handoff.md section 4

## Goal
Pin the actual Pi dependency and prove that required public APIs can support Macus Code without duplicating the Pi agent loop.

## Scope
Implement an internal AgentKernel / PiAgentKernel boundary with stable Macus DTOs. Verify exact Pi package/version/commit and supported APIs for session create/resume/switch/dispose, streaming model/tool/retry/compaction/run events, explicit user input queue/steering, cancellation, request preparation before every provider request including nested tool turns, centralized tool registration/execution, supported compaction, model switching and recovery of incomplete tool exchanges.

Inspect resource-loader behavior so repository instructions are not loaded twice. Rebind event subscriptions/resources after session replacement where required.

## Deliverables
- Pi adapter module with no Pi-internal imports outside the adapter.
- Compatibility tests using the pinned version.
- docs/pi-compatibility.md mapping every required Macus capability to exact public API/source references.
- Explicit record of unsupported hooks and tested alternatives.

## Acceptance Criteria
- [ ] Streaming works through an async event or iterable interface.
- [ ] Multiple provider requests inside one run pass through the request hook.
- [ ] Tool calls/results remain valid protocol groups.
- [ ] Cancellation reaches model and compaction paths.
- [ ] Session replacement/resume rebinds required resources.
- [ ] No send-only abstraction hides missing lifecycle requirements.
- [ ] No direct mutation of Pi transcript files.
- [ ] Any core patch is justified by a reproduced API gap and maintenance plan.

## Tests
Use deterministic mock-provider tests for streaming, nested tool turns, request interception, compaction, cancellation, session replacement and resume.
